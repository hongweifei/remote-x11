# rx11 控制台 — 设计说明与验证记录

本文记录 `crates/rx11-gui` 的设计取向、可核对的取舍依据，以及交付前的验证证据。
文字面向"下一个要改这个界面的人"，不是产品宣传。

## 1. 定位与推导

**品类**：网络链路工具的控制台（同一品类里风格最鲜明的是 Wireshark 的深色密集协议视图、Tailscale 的节点状态台、Grafana 的仪表盘）。

**用户与场合**：本项目作者这类人——自己起中继、自己连客户端、在慢速公网上跑远程 GUI；界面长时间挂在副屏上，主要动作是"看一眼链路是不是在动"和"改一个参数再重连"。

**生成引擎**：本产品的核心对象是**一条被观测的信号路径**（字节从远程 X server 出发，穿过中继与隧道，落到本地 X server）。因此界面借用测量仪器的语言：石墨底、细线分隔、单一琥珀信号色、等宽数字、信号灯状态；而不是通用后台的"卡片 + 阴影 + 彩色标签"。

**首屏结论**：用户来首屏是**看链路、动手启停**，不是读介绍。所以首屏即工作区：顶部一条链路带（`中继 ⇄ 客户端`），下面依次是数字条、示波器、会话表；没有口号、没有说明段、没有装饰插画。

**主动作**：三种角色的启动按钮（中继 / 客户端 / SSH 隧道），它们在右上"启动"卡片里，与它们要用到的令牌相邻。

## 2. 视觉语言

**色彩**（`theme::C`，全部为 `0xRRGGBB`）

| 角色 | 色值 | 用途 |
|---|---|---|
| 底色 | `#0E1013` | 窗口底 |
| 面板 | `#15181C` | 卡片、侧栏、日志井 |
| 抬起 | `#1C2026` | 输入框、悬停行 |
| 按下 | `#242A31` | 选中/按压 |
| 凹陷 | `#0A0C0E` | 示波器与日志的底 |
| 细线 | `#23282E` / `#333A43` | 分隔；后者用于结构性分隔 |
| 主文字 | `#E8EBEF` | 正文与数字 |
| 次文字 | `#99A2AC` | 标签、说明 |
| 弱文字 | `#66707B` | 单位、时间戳 |
| 信号琥珀 | `#F2B23C`（亮 `#FFC96B`，暗 `#A07A2A`） | 运行中、主动作、示波器主迹 |
| 沙色 | `#8C7A5E` | 示波器副迹（上行），与琥珀同一色系 |
| 状态 | 绿 `#4FBF8F` / 黄 `#E8A33D` / 红 `#E0604A` / 灰 `#5A636D` | 仅用于状态，且**永远带文字标签** |

规矩三条：
1. **一个色相承担含义**。琥珀=活着/可操作；其余全是石墨中性色。所以一屏里"这是主角"和"这是背景"不需要第二种强调色来区分。
2. **颜色从不单独承载状态**。每个状态点旁边都有文字（运行中/重连中/已失败），灰度截图也能读。
3. **密度是特性**。正文 14、标签 13、微标签 12、数字等宽；这是给人盯几小时的工具，不是海报。

**字体**：中文面 Noto Sans CJK SC（`ui_font`），数字/地址/日志 JetBrainsMono（`mono_font`）。
给 FLTK **控件**（输入框、下拉）一律用 `widget_font()`——即 FLTK 的默认字体槽。原因见第 5 节。

**布局常量**（`theme::L`）：顶栏 58、侧栏 236、状态栏 28、外边距 22、卡片间距 14、圆角 6（仪器是机加工边，不是枕头边）。所有页面从这一组数推导，改一处不会让某页错位。

## 3. 页面结构与信息层级

```
┌ 顶栏 ── 中继 ●──⇄──● 客户端 ── 速率 · 累计 ── [保存全部] ┐
│ 侧栏      │ 工作区                                        │
│ 链路总览 ●│ 页标题 + 一句话用途 + 细线                    │
│ 服务端  ①│ 数字条：下行/上行/压缩节省/累计/活动通道        │
│ 客户端  ①│ 示波器（90 秒包络 + 悬停读数） │ 启动卡片       │
│ SSH 隧道  │ 会话表：角色/状态/对象/流量/操作               │
│ 运行时    │                                               │
│ 日志      │                                               │
├ 状态栏 ── 配置文件路径 · 未保存 · 提示 ── N 个会话 · 运行时间 ┤
```

- **页面标题块**：标题 + 一句话用途 + 收口细线。每个页面都回答"这页是干什么的"，但不写段落。
- **数字条**：五个格子，等宽数字，右对齐；单位小字跟在数字右下。零值显示为 `0 B/s` 而不是隐藏——空链路也是信息。
- **示波器**：见第 4 节。
- **示波器顶部**：绘图区上方留一条 24 单位高的 gutter，里面只有一行——左边峰值刻度、右边实时读数，**两者同一个 y**。峰值的刻度标签放 gutter 里而不是压在绘图区上边缘（原来它整条基线跨在顶边上），中间和底部两条刻度线仍按图表惯例各自居中于自己的线。

- **会话表**：列宽固定（角色 86 / 状态 96 / 流量 132 / 操作 54），对象列吃掉剩余宽度；长名称用省略号而不是裁一半。
- **表单页**：左侧字段卡（标签固定 190 列 + 输入框 + 提示行），右侧动作列（保存/重新载入/恢复默认、校验状态、作用范围说明）。服务端/客户端/SSH 三页在右下角还有一对启停按钮；「运行时」页**没有**——它不拥有任何一端，放一个"启动"只会让人猜它启动谁。
  - **表单页可滚轮滚动，且必须有可见的滚动提示**。运行时页有 20 个字段、内容总高约 1516 逻辑单位而可视区只有 714——**在加滚动之前，一半字段根本到不了**（几何里 `scroll` 一直存在，但没人喂它）。现在滚轮一格移动约 1.5 行、按 `content_h - view_h` 夹紧。
  - **滚动提示**：字段列右侧画一条 4 单位宽的滚动条（轨道 `RAISED`、滑块 `TEXT_3`），只在内容装不下时出现，装得下的页面保持干净。**滚轮是看不见的交互，没有这个提示没人会发现下面还有内容**——这是用户明确要求补的。
  - **可视带必须与绘制用同一个判据**。`scroll_band()` 算出可滚动区域的矩形，`paint` 用它 `push_clip`，`place_fields` 用 `row_fits()` 决定控件显隐：**整行（输入框到提示）都在带内才显示**。之前两者判据不同，出现两种穿帮——半行标签被裁掉而输入框探出到页头之上、以及只剩一个没有标签的开关悬在卡片边缘。FLTK 控件的绘制度不受画布 clip 约束，所以只能靠"要么整行显示、要么整行隐藏"来对齐。
  - **提示行必须贴着自己的输入框**。曾经 `hint_y = fy + 36`，实测「输入框底 → 提示中心」18 设备像素、而「提示中心 → 下一行输入框顶」只有 11——提示读起来像是属于下面那一行的。改成 `fy + 31` 后是 **上 12 / 下 17**，分组关系就对了。这类间距要用"上下两段实测值"判断，不要凭感觉调：测量脚本直接取输入框填充色的行范围和提示文字墨迹的行范围。
- **日志页**：第一行搜索 + 级别 + 导出/清空/复制，第二行各级别计数 + 可见条数，下面是等宽列表（级别三字母 + 时间 + target + 消息，列宽固定）。
- **滚动**：三处列表共用 `ui/scrollbar.rs` 的 `ScrollBar`——配置页的字段列、总览的会话表、日志页的日志流。它只负责"几何 + 绘制 + 命中测试"，页面自己决定滚动对数据意味着什么。**只在内容装不下时出现**，装得下的页面保持干净；滑块长度 = 可视比例，位置随偏移走；**可拖拽、可点轨道翻页、支持滚轮**（滚轮是看不见的交互，光有滚轮等于没有出口）。
  - 会话表与日志流**按窗口开窗绘制**：`scroll` 是行索引不是像素偏移，绘制、命中测试（含行内"停止"按钮）和滚动条都从同一个开窗结果推导。
  - 日志页滚动离开底部会退出"跟随"（顶部提示 `已暂停跟随 · 滚到底部恢复`），滚回底部自动恢复。
- **底部带**：状态栏（配置路径 · 未保存 · 提示 —— 会话数 · 运行时间）只铺在内容列，侧栏那一格放版本号；两者**必须同一条带、同一条上边线**。曾经侧栏页脚写在 `y + h - 54` 并配一条内缩分隔线，结果版本号比状态栏文字高 **40 设备像素**，左下角留出一条空面板——现在页脚改用 `y + h - L::STATUS_H`、以满宽 `hline` 接上状态栏的线，实测两者文字中心完全重合（982 vs 982）。
- **启动卡片（链路总览右栏）**：标题、三个启动按钮、令牌块。令牌块是三行——`令牌` 标签 / 令牌值 + `复制` / 一句规则说明——三行各有自己的盒子，**不要用 `ty`、`ty+10`、`ty+30` 这种相对偏移**：那样标签和令牌值会重叠 4 个单位，`复制` 按钮横跨两行。现在写成 `token_label_y = y+114`、`token_value_y = y+130`、`token_hint_y = y+152`，`复制` 落在令牌值那一行（`by+83` 正好居中于 `y+140`）。实测行距：SSH 按钮底→标签 17、标签→令牌值 10、令牌值→提示 12（设备像素），`复制` 与令牌值同一中心。

**已知取舍**：会话表超过可视行数时不再滚动，而是只画能放下的行（数据层仍保留全部会话）。这是留给下一轮的工作，不是"设计如此"。

## 4. 记忆点：链路示波器

选它的理由来自产品本身：这个工具做的事情就是"把一条字节流搬过去"，所以最该被看见的是**流量的形状**。

- 两条迹：下行（中继→本地，画面主体）画实心包络 + 亮线；上行（本地→中继）画细线。同一色系的两个明度，不引入第二个色相。
- 纵轴按 1/2/5 取整（`nice_ceiling`），因为桌面流量跨三个数量级：线性轴会让除洪峰以外的一切都贴地。
- 悬停出十字线与读数（`-57.5s · ↓18.6 KB/s ↑1.3 KB/s`），把"大概多少"变成"确切多少"。
- 顶部右侧常驻当前速率，让同一信息既有形状也有数字。
- 空闲态是平线 + `无活动链路`，不伪造波形。
- 视口底边不放半行：字段行只有标题**和**提示都放得下才绘制，宁可少一行也不出现被切一半的中文。

## 5. FLTK 工程结论（都是踩出来的）

这些不是风格选择，是这套绑定/版本的实际行为，已在 `examples/layer_probe.rs` 与源码中复核：

1. **组按创建顺序画子控件**，后创建的在上。因此页面背景必须是**第一个**子控件。
2. **重画一个子控件不会重画它的兄弟**。所以"只重画背景"会把控件擦掉；页面变更一律走 `Page::redraw()`（整组重画），并且应用每 0.5 秒轮询时重画当前页——一秒两次整页重画的开销可以忽略，换来"不会莫名少一个控件"。
3. **被隐藏后重新显示的控件没有 damage**，FLTK 的局部重画会跳过它，内容就永远不出现。`set_widget_visible` 在 `show()` 之后补一次 `redraw()`。
4. **FLTK 控件不能直接用按名字取到的字体索引**：`set_text_font(Font::by_name("Noto Sans CJK SC"))` 在本机会画出不可见字形，而同一索引交给 `draw::set_font` 自绘却正常。控件一律用默认槽 `widget_font()`（`init()` 已把默认槽映射到中文面），输入框文字色用全强度 `#FFFFFF`（`C::WIDGET_TEXT`），0xE8 档在本机会画不出来。自绘文字不受影响，继续用 `C::TEXT`。
5. **文字用 `fl_draw(str,x,y,w,h,align)` 的"框"形式会整体偏低**：没有 TOP/BOTTOM 标志时，FLTK 把基线算成 `y + (h-line)/2 + line`——加的是**整行高**而不是**上行高**，于是每个标签都比视觉居中低了一个 `descent`（本机 12–14px 字号下 3–4 单位 / 4–5 设备像素，"看着总是往下一点"就是它）。`theme::text` 因此自己算基线：`y + (h-line)/2 + (line - descent)`，并用基线版的 `draw::draw_text` 画；水平锚点也自己按 `measure` 算（`Align::Center` 是"没有 Left/Right"的标志位，判定顺序不能反）。A/B 实测：同一行文字从"低于行中心 4.3px"变成"与行中心重合"。
6. 窗口必须**先创建**、控件后创建（否则控件不属于任何窗口，整窗空白）；而页面显隐要在 `win.show()` **之后**决定，不然窗口自己的 show 会把隐藏页翻出来。
7. 组 `hide()/show()` 会带上全部子控件，所以切页是一次调用，不需要逐个 `show/hide` 记账。
8. 本机窗口由 Hyprland 平铺，截图前要 `hyprctl dispatch setfloating` + `xdotool windowsize` 把窗口钉成 1475×1000（1180×800 @1.25），否则每次截出来的尺寸都不一样，前后对比就没法比。
11. **`card()` 会画卡片，不能当测量函数用**。`ui::chrome::card(x,y,w,h)` 的名字像"求内框"，实际先 `fill_round` + `stroke_round` 再返回内框。本轮把滚动条的几何 helper 写成调 `card()`，结果**每帧在内容之后又重画一次卡片**，把已经画好的行全部盖掉——表现为"列表整块空白，但标题和卡片边框都在"。凡是只需要几何、不参与绘制的地方（滚动条、命中测试、输入处理），一律用纯算术（`card` 的内框是 `(+18, +16, -36)`），并在这个 helper 上写明原因。
12. **一个页面里同一块区域的几何只能有一个来源**。本轮踩了两次：滚动条用页面高度算可见行数、而绘制用列表高度，于是滚动停在空帧上；会话表的行数 helper 又漏算了卡片以上的区域。修法是抽出 `scroll_band()` / `sessions_rect()` / `list_rect()` 这类函数，绘制、命中测试、滚动条、输入处理全部从它取值。

9. **文字与标记点都对齐"盒子的光学中心"，而这个中心不是行盒的中心**。用户两次报「文字向下了一些」，根因是：行盒（ascent+descent）里给降部留了一条带，而汉字几乎填满整个 em 方框、拉丁小写只占 x-height 带——所以**按行盒居中**时，汉字会低 3–7 逻辑单位（按钮 +4.0、页标题 +7.0、表单标签 +3.0），拉丁/数字则基本正好。修法是把"居中"的对象从行盒换成**墨迹**：
   ```text
   baseline = y + h/2 + ink_above_baseline(文字, 字号)     // text()
   center_y() = y + h/2                                     // LineBox，标记点用
   ```
   两者由同一个盒子导出，所以圆点、图标和文字不可能再各自漂移。`LineBox` 携带标签的盒子，`line_text()` 让标签也从它画出来。
10. **`ink_above_baseline` 的两个系数是实测标定值，不是推导值**。在 `set_screen_scale` 下 FLTK 会把缩放后的文字内部偏移 `-1`（`Fl_Scalable_Graphics_Driver::draw` 里那句 `int offset = (scale() == 1 ? 0 : -1); // for issue #1308`），于是 `fl_height()`/`fl_descent()` 推不出真实渲染基线——我按这个思路连推三版公式（x-height / ascent / cap-height），每版都被下一次实测推翻，那是在猜参数而不是解题。最后改为量出来：`examples/calibrate.rs` 把真实标签和一组候选偏移的圆点画在同一张图上，读像素得到**拉丁 0.355 em**（约半个大写高）、**汉字 0.115 em**。**改字号、换字体或改 UI 缩放后要重跑这个 example 重新标定**（那个 −1 偏移本身就是缩放相关的）。
   实测（同一位置、1.25 缩放、设备像素）：

   | 项目 | 修复前 | 修复后 |
   |---|---|---|
   | 按钮「保存」文字相对按钮盒中心 | +3.5（偏下） | **0.0** |
   | 表单标签相对其输入框中心 | +4.0（偏下） | **+0.5** |
   | 顶栏节点 圆点相对文字墨迹中心 | −3.5 | **0.0** |
   | 品牌词标 圆点相对文字 | −0.5 | +0.5 |

   代价是所有汉字标签整体上移约 3 设备像素（六个页面的内容区 AE 约 0.6–1%），这是修的就是这个偏移本身；输入框等 FLTK 控件不受影响。

## 6. 代码结构

界面不是"一个窗口 + 一堆回调"，而是六层单向依赖。这一节是给改它的人看的：改哪一层、
不许往哪边 import、以及哪些地方是**故意**看起来绕的。

### 6.1 分层

```text
settings / launcher      领域与数据：config.toml 模型、进程内会话编排、日志环
        ↓
      model              跨层契约：Backend 端口 + 两端交换的数据类型
        ↓
  theme / state / ui     表现层：视觉规范、视图状态、页面与自绘控件
        ↓
 backend / demo          端口的两种实现：真实数据层 / 演示样例数据
        ↓
        app              组合根：窗口、路由、0.5 s 轮询、动作翻译
```

| 模块 | 文件 | 职责 |
|---|---|---|
| `settings/**` | 8 | `config.toml` 双向模型：`paths`/`error`/`model`/`validate`/`flat`/`io` |
| `launcher/**` | 4 | 会话编排：`mod`（生命周期）/`logging`（日志环）/`session`（模型与隧道）/`record`（运行时簿记） |
| `model.rs` | 1 | `Backend` trait + `Role`/`Health`/`LogLevel` + 四个 DTO |
| `theme/**` | 4 | `tokens`（唯一的设计令牌来源）/`fonts`/`draw`（唯一直接调 `fltk::draw` 的地方） |
| `state.rs` | 1 | UI 线程独占的视图状态 |
| `ui/**` | 16 | `mod`（`Page` 表面）/`layout`（声明式布局求解）/`chrome`/`action`/`controls`/`scope`/`shell`/`pages/*` |
| `backend.rs` `demo.rs` | 2 | `Backend` 的两种实现 |
| `app/**` | 3 | `mod`（外壳）/`actions`（动作翻译）/`tests` |

### 6.2 五条规则（都由 `tests/architecture.rs` 断言）

1. **契约层不自知**：`model.rs` 不 import 本 crate 任何模块，也不出现 fltk。它能在没有显示器的机器上编译，所以两端的测试都不需要 X。
2. **表现层只看下层**：`ui/**` 不认识 `app`/`backend`/`demo`/`launcher`/`settings`。页面只负责"画"和"抛出意图"，因此可以脱离真实数据单独渲染 —— `RX11_GUI_DEMO=1` 就是这条的直接收益。
3. **适配器不认识界面**：`backend.rs`/`demo.rs` 不 import `ui`/`theme`/`state`。之前 `demo.rs` 要从 `ui::pages` 借 `LogLevel` 类型，等于让样例数据依赖页面；`LogLevel` 因此被提到 `model.rs`，**颜色映射反而留在页面里**（`ui/pages/logs.rs` 的 `level_color`、`console.rs` 的 `health_color`）——语义在契约层，观感在表现层。
4. **领域层不依赖表现层**：`settings`/`launcher` 与 fltk 完全无关，所以配置与编排有完整单元测试而无须开窗口。
5. **入口不拥有模块**：`main.rs` 只有一行 `rx11_gui::run();`，模块树归 `lib.rs`。之前一半模块在 `main.rs`、一半在 `lib.rs`，从任何一个入口都看不出架构，`tests/` 与 `examples/` 也够不到真正的模块。

规则检查是**故意做笨的**：读源码文本、只看 `use` 语句和文件路径，不引入依赖、不解析语法树。这条测试自己不该成为结构里最重的东西。规则表里新增模块名时会红一次，这是有意的——改依赖方向应该是一次自觉的决定，而不是顺手 import 一下。它会检查的其它三件事：单文件不超过 1000 行（拆分前 `settings.rs` 1809 行、`launcher.rs` 1802 行）、每个 `.rs` 都被父模块声明（重构留下的孤儿文件编译不到）、以及 **`draw_text2` 不得重新出现**（见第 5 节第 5 条，那是文字偏低那个 bug 的复发标记）。

### 6.3 数据怎么过河

界面与数据层之间只有一种语言：**扁平 `key → string` 值**（如 `("server.port", "17000")`）加上快照结构。所以：

- 界面永远不知道配置文件的 schema；
- 新增一个运行时开关 = 一个 `FieldSpec`（`ui/pages/config.rs`）+ 一行配置层代码，中间没有别的地方要同步；
- 四个配置页是**声明式字段规格**（`FieldSpec`/`SectionSpec`/`FormSpec`）由一个表单引擎（`ui/pages/form.rs`）解析，**不要**给某个页面手搭控件树。

`Backend` 端口一共 11 个方法，实现两份：`backend.rs`（真实：`GuiConfig` ↔ 扁平值、`Launcher`、`LogRing`）与 `demo.rs`（固定样例数据，feature `demo`，默认开）。`demo` 收进 feature 是为了让"只含真实数据层的精简构建"成为一个开关而不是一次删代码（`--no-default-features`）；设了 `RX11_GUI_DEMO=1` 却没编进 demo 时会明确报错退出，**不会**悄悄退回真实数据层（那会让取证脚本拍到一份"看起来正常"的空数据）。

### 6.4 文件拆分（2026-10-22）

同一天做了五轮**纯结构重构**，全部满足：不改行为、不改界面、不改公开路径、不加/不删测试。

| 原来 | 现在 | 关键手法 |
|---|---|---|
| `settings.rs` 1809 行 | `settings/` 8 文件 | `mod.rs` 是门面：`pub use` 出原全部 13 个公开项，调用方一行不改即编译 |
| `launcher.rs` 1802 行 | `launcher/` 4 文件 | 同上；`session.rs` 按 3 文件切会到 737 行，于是按职责再分出 `record.rs`（内部簿记 vs 对外会话模型） |
| `theme.rs` 492 行 | `theme/` 4 文件 | `mod.rs` 27 项 `pub use`；令牌/字体/绘制三层，`draw.rs` 是唯一碰 `fltk::draw` 的 |
| `ui/mod.rs` | `+ ui/chrome.rs`、`ui/action.rs` | 三个页面各自复制的 `ActionSlot`/`emit` 去重成一份泛型；`Action` 改名 `TopbarAction` |
| `ui/pages/settings.rs` | `ui/pages/config.rs` | 消掉与 `src/settings/` 的重名歧义；`pages/mod.rs` 保住旧路径 |
| `app.rs` 934 行 | `app/` 3 文件 | 动作方法写成子模块里的 `impl App { … }`：**固有 impl 可以跨文件**，方法语义与可见性都不变 |

两条来自"搬家"的通用经验：

- **公开面在哪里决定要不要 `pub use`**。`settings.rs` 那轮公开项在原单文件里，所以门面必须重导出；`app.rs` 那轮 `App`/`POLL_INTERVAL` 本来就是模块项，`mod.rs` 自己就是公开面，加了反而多一层。两种情况下"没有改过任何调用方文件"都是最硬的证据。
- **去重和改名是合法的计数变化，必须逐条说明**。三个 `ActionSlot` 合成一个是改进，不是丢失；只报一个总数等于没说清。

**怎么证明"只搬家"**（这个 crate 在 git 里没有历史可回退，所以方法本身要写下来）：动手前把 `src/` 快照到 `/tmp`；改完做三件事——① item 普查（旧文件的每个 `fn/struct/enum/trait/const/static/impl` 名字在新树里还在，`impl` 按目标类型集合比，因为一个 `impl` 块可以合法地拆成两块）；② 归一化行级 diff（抹掉 `use`/`mod`/`pub use` 与 `pub(super)` 前缀后逐字节比对，**唯一允许的差异是可见性放宽**，注释行不在白名单里）；③ 门禁 + 测试函数名集合 diff。行为层再补一次 `cargo test --workspace`、一次隔离 HOME 的适配层端到端，以及截图的逐像素 A/B。

### 6.5 声明式布局（2026-10-22）

界面过去是手算坐标：页面里到处是 `x + pad`、`y - L::STATUS_H`、`first_row_y + i * ROW_H`。这类代码反复出错，而且每次错的都是**同一类**毛病——同一块矩形在两个地方各算一遍，于是画出来的和点得到的不一致：

| 症状 | 原因 |
|---|---|
| 滚完列表停在空白帧 | 滚动条按页面高度算可见行数，绘制按列表高度算 |
| 滚轮判"不需要滚动" | 行数 helper 漏算了卡片以上的区域 |
| 会话表滚动条画到窗口外 | helper 收的是卡片矩形，却按整页矩形解释 |
| 最后一行会话画到卡片外 | 可用高度漏减了内边距 + 标题 + 表头 |
| 日志井最后一行与滚动条戳出井外 | 行数与轨道长度各自减一串魔数 |

修法不是"再仔细一点"，而是让这些矩形**只有一个来源**：`ui/layout.rs` 是一个一维布局求解器，页面把自己的版面描述成一棵树，求解一次，然后绘制、命中测试、滚动条、容量计算全部读同一组 `Rect`。

```text
Layout::column() / Layout::row()      创建根栈
  .leaf(parent, Size)                 叶子：页面要绘制的区域
  .stack(parent, Axis, Size)          子容器
  .pad(id, Insets) / .gap(id, n)      内边距 / 子项间距
  .lead(id, n)                        插在该子项之前的间距
solve(Rect) -> Solved                 求解；solved.get(id) 取回矩形
```

尺寸三态：`Fixed(n)` 精确占据、`Hug(n)` 内容需要多少就多少（装不下时让位，这是它的契约而非错误）、`Fill(w)` 按权重瓜分剩余空间。子项**永远不会**越出容器：固定尺寸之和超出时，`Solved::overflow()` 报真、靠后的子项被压缩。这一条是有意的——"画到容器外面"正是这套东西要消灭的症状。

页面文件里因此不再出现 `+ Metrics::…` 形式的坐标推算；`console/mod.rs`、`logs.rs`、`form/mod.rs`、`shell.rs` 里的手算坐标已清零。每个页面一个 `build_layout`（表单页是 `form_layout`），`Rect` 按语义命名（`session_card`、`row_area`、`column_rects`）。

滚动统一表达为**求解一次再平移**：表单页按内容的自然高度求解，`Solved::shift(-scroll)` 平移整棵树。滚动因此不会退化成第二套布局——正是这套东西要消灭的那种重复。

**判据（改版面时照做）**：几何函数是纯函数，不依赖 FLTK 绘制，所以能直接断言。`ui/layout.rs` 有 11 条不变量测试（子项不越界、权重分布、Hug 让位、容量、平移保持相对几何），`console/geometry.rs` 把总览页的卡片栈**钉成具体数字**——它迁移前后必须逐像素等价，改坏了在测试里就红，不必等截图：

```rust
assert_eq!(solved.get(geometry.sessions), Rect::new(22, 510, 900, 182));
assert_eq!(area.y, 588, "首行在卡片顶下方 78");
```

表单页的 `geometry(spec, x, y, w, h, scroll)` **签名不变**：内部改走布局树，返回的 `SectionGeom`/`RowGeom` 数值与手算版一致，所以绘制与控件摆放的调用点一行未改。判据是四页截图逐区域 A/B——字段行、提示行、侧栏位置全部 AE=0。


### 6.6 演示数据的两个尺寸开关

默认演示夹具很小（2 个会话 / 6 条日志），因为交付截图就该是"一个刚配置好的人看到的样子"。但滚动条只在列表溢出时出现（会话表放得下约 7 行、日志井约 25 行），所以手动验滚动需要更大的夹具：

```bash
RX11_GUI_DEMO=1 RX11_GUI_DEMO_SESSIONS=12 RX11_GUI_DEMO_LOGS=200 \
  RX11_GUI_SCALE=1.25 cargo run -p rx11-gui
```

- 会话角色按 服务端 / 客户端 / SSH 轮换，**行与行看得出区别**——否则滚没滚肉眼无法判断（这个坑踩过）。
- 两个值都有上限（200 / 日志环容量），写错了不会让夹具生成器转圈。
- 默认值不变，所以交付截图与默认 `RX11_GUI_DEMO=1` 的渲染完全一致。

## 8. 明确没做的事

- **SSH 会话没有在 GUI 里真跑过**：只在适配层做了参数校验与结束原因映射，没有起真实 `ssh` 进程。要证据的话，按 CLI 的 fakebin 办法补一个 ignored 测试即可。

- **没有打包/安装**：只提供 `cargo run -p rx11-gui` 与 `target/release/rx11-gui`，没有 `.desktop`、图标或安装脚本。
- **没有做托盘/后台驻留**：窗口关掉即停掉由它启动的会话（这是当前明确行为，不是遗漏——但如果你希望"关窗继续跑"，那是另一套语义，需要先定）。
